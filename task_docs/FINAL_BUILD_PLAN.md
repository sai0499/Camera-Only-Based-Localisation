**The decision**

Build a causal camera localizer with three sources of evidence: a small visual landmark map for absolute position, surveyed borders for conservative lateral/heading correction, and short-term visual tracking for continuity. Use one six-state filter and explicit loss/recovery states. Start with `fr`; add `r` as the second camera. The first demonstrable result is a continuous, scored trajectory; the final differentiator is measured failure detection and recovery with honest accounting of every output.

Build the hybrid with a **declared, frozen fitting-only visual map** as the default development system. The README permits GT for training, so treating this fitted map as a trained artifact is the explicit working interpretation, not an organizer confirmation of this artifact type. It contains no query-time GT access, hidden-run fitting or timestamp-to-pose lookup. Package the supplied-border/ground-motion mode too, sharing geometry/reader/filter. If the organizers explicitly disallow the fitted visual map, select that existing strict mode and disclose its measured longitudinal drift; do not invent an equally accurate fallback. No unanswered rule question blocks implementing either path. The whole live state-estimation topic remains excluded in every mode.

**Final changes from the earlier research**

| Earlier proposal | Final build decision |
|---|---|
| Border matching as the main absolute locator | Prefer geometrically verified landmark poses; borders cannot resolve position along a uniform straight |
| A nine-state optimization and up to three filter modes | Six-state temporal filter; z/roll/pitch are auxiliary projection geometry; one active pose and one uncommitted recovery candidate |
| SuperPoint as initial feature choice | DISK + LightGlue, already supported together; retain SIFT only as a setup-failure fallback |
| General multi-camera fusion | `fr` first, `r` second; choose one verified absolute pose per update instead of assuming correlated poses are independent |
| Simultaneous landmark and border optimization | When a landmark pose passes, update once; otherwise allow a restricted border correction |
| Unspecified camera-derived motion | Mapped-point tracking/PnP first; explicitly scale ground-motion estimates through a checked local road plane |
| Adaptive camera scheduling, particles, new segmentation model | Outside the 48-hour critical path |
| Expensive matching allowed per camera group | One worker with bounded jobs per second and current-image correspondence handoff |
| Fixed per-frame process noise and 0.5 velocity smoothing | Continuous-time covariance, second-based smoothing and capped repeated-observation information |
| NetVLAD recovery added only after loss | Compact EigenPlaces retrieval warmed early, with immediate geometry-verified recovery requests |

DISK/LightGlue is an implementation and packaging choice, not a proven accuracy advantage on this data. The LightGlue maintainers distinguish its/DISK's licensing from SuperPoint's; include the actual code/weight notices used. Reuse hloc/pycolmap for known-pose triangulation and OpenCV for PnP and tracking. Do not implement a new SfM engine. [LightGlue documentation](https://github.com/cvg/LightGlue), [hloc documentation](https://github.com/cvg/Hierarchical-Localization).

**1. Fixed input/output contract**

Allowed inference inputs for the original task remain image messages, each run's camera calibration, camera-to-body transforms, the supplied XYZ border map, one initial timestamp/x/y/yaw, and permitted frozen training artifacts. Use `23-00-38_cut_120m_update/map.mcap` as the canonical static asset: its four surveyed borders are identical to the original bag's border map, and its reference Paths define track-coordinate outputs. Keep original `/track_bounds` as a compatibility check, not duplicate evidence. Reference lines can express the estimate's progress/offset without providing a new measurement; any extra inference-prior use still follows the selected option's rules. The native-coordinate bridge is an offline evaluation artifact, not a live GT input. The estimator must not decode or receive dynamic `/tf`, state-estimation fields (including native s/n and lane), GT CSVs, or an evaluation callback. A separate evaluation harness may read GT and export the one initial pose.

Use signed integer nanoseconds internally. The submission is exactly `timestamp_ns,x,y,yaw`, where x/y describe `constructor0/base_link` in `map` in metres and yaw is radians. Diagnostics go into a separate JSONL file. Emit a finite pose for every completed input group, including low-trust outputs. Record processing failures and incomplete input periods rather than hiding them.

Read the driving MCAP in recorded arrival order. Load the separate static map once before inference; its own message times are not run-start or camera times. Consume the first available camera/static calibration payloads before initializing; validate later payloads for compatibility instead of silently switching geometry. Camera metadata is checked for all seven streams, but only selected images need JPEG decoding. Static non-camera transforms are discarded.

Let T be the median of the last 16 valid primary-camera exposure intervals available when a group opens, initially 100 ms. Freeze that cadence snapshot for the group. Use exposure tolerance **min(5 ms, 0.2*T)** and arrival deadline **min(40 ms, 1.2*T) after the first selected image arrives**. Form exposure-ordered `fr`/`r` groups; close when both arrive or the deadline expires. At most four groups may be pending. If opening another would exceed four, close/emit the oldest with its available views and log a capacity closure; this handles startup/rate changes without deadlocking the reader behind an unread support packet. No group is deleted. A camera appears at most once in a group and an image is never reused as a new observation. Replay timers use recorded log time, not CPU completion time; a live adapter uses actual arrival time. Future groups stay buffered and contribute no visual evidence or cadence changes to earlier groups. Late support is dropped/logged; duplicate/decreasing per-camera exposure stamps are rejected without shrinking uncertainty. A missing rear image does not replace the current rear slot with the next exposure.

The final timing audit found paired front/rear arrival spread median 4.140 ms, p95 11.699 ms, p99 15.299 ms and maximum 36.113 ms. A half-period timeout at 60 Hz would reject 17.68% of those recorded pairs. The chosen 20 ms deadline at 60 Hz exceeds that measured p99, with bounded overlap between groups. These are observations of the original 10 Hz recording, not proof of native 60 Hz transport performance.

Stamp the output at the maximum exposure in the accepted group, whether or not both views yielded valid features. Every supporting image must have exposure <= that stamp. Propagate measurements from their own exposures to that reference time using the current causal motion estimate. Do not shift exposure times by the observed approximately 42 ms publication delay. Only use images at or after the initial-pose timestamp. A terminal partial group can be flushed once, explicitly flagged; completed-group prefix tests exclude that special EOF event.

Confirm the image-set stamp convention with organizers. For ablations on the same input, grouping is independent of whether a frontend is enabled, so all variants have identical output timestamps. If both selected cameras disappear, the baseline has no image-set event: log the coverage gap; do not invent an image timestamp. Adding another camera to the group is an explicit, tested configuration change.

**2. One pixel convention and one geometry implementation**

Let `T_AB` transform coordinates from B to A. Read camera extrinsics as `T_BC`. A world point is projected using `P_C = inverse(T_WB T_BC) P_W`. OpenCV PnP returns `T_CW`, so the required body pose is `T_WB = inverse(T_CW) inverse(T_BC)`. Store quaternion order explicitly as xyzw; convert at library boundaries.

Canonical images are RGB **960 x 464**, with an undistorted pinhole camera model. Cache a direct raw-to-canonical map using raw K/D, identity rectification R, the target K below and the final output size. `initUndistortRectifyMap` followed by one `remap` combines undistortion/downsampling in one interpolation; do not remap a full native-sized image and resize it again. Keep masks for remap-invalid pixels/bodywork. Do not use supplied P as an alternative raw K. This revision requires a new preprocessing ID and freshly built reference features/triangulation: equivalent ideal rays do not imply identical pixel values to the old two-pass method. Apply the same map to fitting/query images.

For OpenCV's half-pixel resize convention use `fx'=sx*fx`, `fy'=sy*fy`, `cx'=sx*(cx+0.5)-0.5`, `cy'=sy*(cy+0.5)-0.5`, with actual sx=960/1506 and sy=464/728. Downstream D is zero. Disable feature extractors' extra resizing or explicitly map their returned coordinates back to this canonical space. DISK's wrapper has its own preprocessing default; do not assume it is disabled. Validate with synthetic projections and image overlays. [DISK wrapper](https://raw.githubusercontent.com/cvg/LightGlue/main/lightglue/disk.py).

Keep OpenCV-style pixel centers internally. At the hloc/COLMAP boundary, match the library's pixel-center convention once: hloc's importer already adds 0.5 to feature coordinates; its imported camera model must be consistent. Check a projected-point round trip through the actual installed mapper. Do not manually shift features a second time. [hloc importer](https://raw.githubusercontent.com/cvg/Hierarchical-Localization/master/hloc/triangulation.py), [COLMAP calibration conventions](https://colmap.github.io/faq.html#using-calibration-from-opencv-kalibr-or-other-tools).

Retain all four ordered XYZ polylines. Main-track borders are closed; pit borders are open. Build separate spatial indices and local tangent estimates. Left/right arrays have different lengths and are not index-aligned. For an approximate local road patch, associate nearby opposing segments by compatible tangents, approximately perpendicular separation, and monotonic progress within the same branch; reject crossings and intersections. Fit a small plane to the paired local segments and record residual/support. Do not create a dense road mesh.

Use `/constructor0/map_markers/rr` as the canonical border representation from the new map. Its four XYZ arrays match the old bag's border markers exactly. The corresponding `/constructor0/map_paths/rr/*` topics duplicate that geometry: the main-track Paths omit the repeated closing point, while their markers include it. Do not count Paths and markers as two independent observations or leave a main loop open when using Paths.

The initial pose provides no guaranteed z/roll/pitch. Initialize them from a valid local patch and a fixed body-to-road height offset estimated robustly on fitting data; keep them low-trust until verified PnP supplies full pose. **3. Absolute localization: small frozen map, verified pose**

Member B owns this component. Fit on the supplied `build_split.json` fitting interval only. Interpolate training position and quaternion at each keyframe's exposure, compose the camera pose, and keep world coordinates fixed. Start with approximately 100 `fr` keyframes from a fitting-only segment to prove triangulation and localization; do not begin by processing the full bag.

Build the initial full bank from one complete main-track traversal plus the initial pit traversal, both inside the fitting split. Select by 4 m travel or 5 degrees heading change. Fill uncovered sectors from other fitting laps before adding redundant repeat appearances. Aim for at most 2,000 camera images total across `fr`/`r`, and inspect coverage before enforcing that cap. A missing sector is an explicit map limitation. Match each reference to at most 8 nearby, viewing-compatible references with useful temporal baseline; never exhaustive-match all images. The front and rear views do not need to overlap each other to share the metric map frame.

Use **DISK depth weights**, native NMS window 5, up to 1,024 retained unmasked keypoints, RGB in [0,1], and the DISK-specific LightGlue checkpoint. Disable extra extractor resize explicitly. Start LightGlue with flash auto-detection, depth confidence 0.95, width confidence 0.99, threshold 0.1, mixed precision off and compilation off. An optimization may enter only if its fixed fitting-clip accepted-pose rate does not decrease, pose difference stays below 0.02 m/0.05 degrees, and p95 latency improves; otherwise keep baseline settings. Reuse identical offline/online extraction. If the stack fails the 90-minute setup checkpoint, use SIFT with reciprocal ratio matching and rebuild its references. Never mix descriptor spaces. Freeze actual package/weight hashes only after the smoke test; source revisions and binary availability checked during research are in `evidence/dependency_source_review.json`.

Use hloc/pycolmap known-pose triangulation with fixed poses and fixed intrinsics. Verify those poses remain fixed in the produced artifact; do not run an unconstrained reconstruction and align it using validation GT. Require at least three fitting observations per retained landmark, positive depth, triangulation angle >=1 degree, and median reprojection error <=2 canonical pixels as starting gates. Mask bodywork and manually identified moving vehicles in reference images; reject tracks inconsistent with the fixed camera geometry. Review the map's coverage/geometry instead of treating a large point count as success. [Known-pose reconstruction](https://colmap.github.io/faq.html#reconstruct-sparse-dense-model-from-known-camera-poses).

At runtime, track at most **512** active points with forward/backward pyramidal LK and solve PnP on valid mapped tracks each group. Initialize LK from projected known landmarks when geometry is valid; an initial guess is never accepted evidence by itself. Learned descriptors/matching run in the bounded worker specified in section 3a. Trigger refresh on 0.5 s elapsed time, fewer than 40 tracks, 8 m travel or 8 degrees yaw change since the last refresh, subject to its rate limit. Retrieve spatially plausible, viewing-compatible references from the filter snapshot, not training lap time. Expand search with uncertainty; in recovery use global retrieval without a falsely tight position cutoff. Merge references only with unique query-keypoint and 3D-landmark identities: duplicates through different database views cannot count as extra PnP inliers.

Use RANSAC PnP followed by pose refinement on its inliers. Starting acceptance gates: >=30 inliers, >=35% inlier fraction, median error <=2 px, p90 <=4 px, support in >=6 cells of a 4 x 4 image grid, and valid positive depths. Test for nearly collinear/degenerate geometry; inlier count alone is insufficient. Convert to body pose before innovation checks. Initial innovation limits are 5 m and 10 degrees or a larger three-standard-deviation bound from the filter; an out-of-gate result becomes a recovery candidate, not a forced update. These thresholds are tuning defaults, not promises of correctness. [OpenCV PnP](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html).

`fr` is the primary camera. Add `r` after the first forward-camera trajectory works. Normal anchor rates are 2 Hz front and 1 Hz rear, staggered; recovery allows at most four jobs per second total. Each job matches at most two references. During healthy front tracking, decode rear anchor frames and the rear image chain while its anchor is in flight through delivery/rejection; decode/track rear each group when front support fails. This supplies a current same-camera image for handoff without permanently decoding every rear frame. Pairing rear headers alone requires no JPEG decode. Do not sum shared-map camera poses as independent observations. If poses disagree by >2 m or >3 degrees at a common time, keep candidates uncommitted and require confirmation; otherwise choose the stronger spatially distributed current pose. Never average incompatible poses.

The map artifact contains landmarks, observations, descriptors, keyframe geometry, calibration/preprocessing IDs and fitting provenance. It contains no test-time trajectory lookup table. Store most reference descriptors in CPU memory and cache a bounded subset on GPU. Keep 2D keypoints in float32, world geometry/calibration in float64 and cached descriptors in float16 where supported; hloc's generic half export must not also downcast subpixel keypoints. A corrected calibration/backend/pixel pipeline requires matching rebuilt geometry/features and a new manifest.

**3a. Bounded scheduling and current-image handoff**

The CPU path handles every completed camera group: primary JPEG decode, one-pass remap, bounded LK/PnP, one estimator update and output. Expensive learned extraction, retrieval and reference matching run in one worker. Allow one job in flight and one latest pending request; replace only unstarted pending requests and log replacements. Normal rates are front 2 Hz plus rear 1 Hz, and the recovery ceiling is four total jobs/s, not four jobs per camera. Each job matches two references at most, so increasing camera frequency cannot multiply the matching budget. Retrieval is a phase inside an eligible anchor job, never an additional independent job; its cost is included in that job's timing. The GPU job target is <=80 ms; it is a profiling gate, not a measured result.

Requests freeze source exposure/group, camera, preprocessing/map IDs, the filter search snapshot and reference candidates. A worker reads only its source image and frozen assets. Results return unique source-keypoint/landmark identities and the source pixels, not a pose to be applied at an arbitrary later time.

Only the main scheduler launches work at logical group boundaries. A worker never automatically dequeues pending work when it finishes. Keep an in-flight job logically occupied until its designated delivery group is processed, even if computation finished earlier; then dispatch the still-valid latest pending request. Thus worker speed cannot decide which request escapes replacement. Requests and rate limits use source time, never catch-up bursts based on wall time.

In ranked replay, designate delivery at the first complete group whose timestamp is at least **source exposure +90 ms**. This normally means about 100 ms at 10/20/30/60 Hz and avoids a nominal 100 ms interval falling a few microseconds short and accidentally delaying a whole extra frame. Polling order does not decide which pose consumes a result. Discard an unstarted request if its delivery group has already committed. If a scheduled in-flight job is unfinished, wait for it and charge the stall to runtime; do not change results according to CPU speed. A backend exception or two-second wall watchdog logs a backend fault and disables further jobs for that run; the camera/ground/border path continues with declared degradation. The real-time profile fails if stalls violate latency gates. Emitted poses are immutable. At EOF, cancel results whose designated group does not exist.

Retain canonical gray images for at most 0.25 s and at most 32 images per active camera. At delivery, carry source matched pixels to the current **same-camera** image through at most four chronological LK transitions, with a cap of 256 candidate points. Select intermediate images deterministically from the buffered interval. Require forward/backward consistency, valid masks and at least the normal unique/spatial PnP support. Solve a fresh pose using the current tracked 2D points and original 3D landmarks. The resulting measurement exposure is the current image, and all source/support stamps must be <= the output group timestamp. Reject old results if source-to-current age exceeds 0.25 s, calibration changed, the image chain is missing or tracking fails. Never propagate an old PnP pose to now and treat it as an independent fresh measurement. OpenCV's LK implementation is reused; no learned optical-flow model is added.

For a 60 Hz stream, the delivery delay normally spans six frames; for 10 Hz it spans one. It is the correspondence refresh that waits, not camera-rate pose output. Existing mapped points keep supporting current PnP while matching runs. After a recovery candidate is found, keep its own small uncommitted track set and verify it on a later current image; confirmation need not wait for another GPU job. This separation makes higher-rate operation plausible; section 8's measurements decide the supported workload. No unlimited-FPS claim is made.

The MCAP reader uses backpressure and bounded buffers; it must not omit hard frames to improve a ranked score. Overflow, worker faults, missing images, rejected anchors and prediction-only outputs are counted in diagnostics. A non-pausable live source needs a separately tested drop policy; it is not advertised as supported by this file-based hackathon runner. Thus the default produces a complete causal dataset replay even if hardware misses a real-time target, and reports the missed target honestly.

**4. Motion and border fallback, with explicit limits**

Mapped tracks followed by PnP provide metric absolute poses when the visual bank is enabled. If they fail or the bank is disabled, try ground motion using only a checked road patch and new image correspondences. In masked road regions, track static corners between consecutive frames; intersect their undistorted camera rays with the estimated local road plane at each exposure. Metric scale comes from the road plane and camera mounting/height, not from normalized essential-matrix translation.

Fit a robust planar rigid transform between corresponding ground points expressed in the previous/current body tangent planes. The fitted transform maps current-body points into the previous body; compose it with the previous world-body pose to propagate the car. Reject near-horizon rays, implausible/negative depths, poorly spread support and non-planar/dynamic matches. Start with depth 3-30 m, at least 30 inliers, >=60% inlier fraction and median ground residual <=0.25 m. Check forward/backward tracking, patch compatibility and rotation sign with synthetic motion. Do not use this model where the road patch changes sharply, is occluded, or has no usable texture. It is approximate metric motion and needs a fitting-only accuracy check before integration.

For ground motion, propagate pose by that delta and grow covariance; do not also treat the same flow as an independent absolute measurement or add it on top of an already applied CV displacement. Estimate map-axis velocity/yaw rate from the accepted delta over its actual exposure interval and smooth with **alpha=1-exp(-dt/0.2 s)**. Preserve/increase uncertainty for the approximate plane and shared previous pose. Compose at the motion record's previous exposure, then propagate to group time using the preceding-exposure state cache. Never revise emitted outputs. If rejected, use brief CV prediction with growing uncertainty. Initial velocity is zero with broad uncertainty and learns only from available images. A long absence of usable evidence is a lost condition.

BorderCast starts with masked gradients/edges and contour orientations in `fr`/`r`; no new segmentation training. Before enabling updates, manually check approximately 50 fitting images covering straight, curve, pit, glare and traffic. Surveyed borders must be associated with actually visible physical boundaries, not whichever bright edge is nearest.

Border corrections run at **at most 5 Hz**, only when current full PnP is unavailable. On one selected current camera, freeze up to 200 branch-compatible visible XYZ samples. Search only lateral shift/yaw with a coarse 9 x 7 grid (+/-2 m by 0.5 m, +/-3 degrees by 1 degree), then a 4 x 4 local grid about its best cell. Including finite-difference conditioning checks, cap evaluation at 85 candidates per update. Hold along-track displacement at zero. Use 8 orientation bins, truncated distance-transform residuals and per-contour caps. Require >=30 supported samples across >=3 separated contours, >=15% improvement and >=80% retained support. A pose cannot win by projecting support off-screen or into a mask. Rate limits use source time, not a frame counter.

Do not enable a border update unless both lateral position and yaw are constrained: examine the two-parameter residual Jacobian with yaw scaled by a 10 m lever arm, and reject a singular/very poorly conditioned fit. These checks are engineering heuristics and require tuning. Reject pit/track associations that are unresolved; keep the previous branch label and expose ambiguity rather than averaging branches. A supplied border is not an exact occlusion model, especially at vertically separated road sections.

When a valid absolute PnP pose exists, use borders for diagnostics initially. When it does not, apply one accepted lateral/yaw border correction. This hierarchy is the deliberate first-build replacement for a joint nonlinear optimizer. Upgrade to simultaneous residual fusion only after an ablation proves it necessary; it is not scheduled in the 48-hour baseline.

**5. Estimator and recovery**

Use state `s=[x,y,yaw,vx,vy,yaw_rate]`, with map-axis velocities and a 6 x 6 covariance. This supersedes the earlier nine-state proposal. Keep z/roll/pitch plus their source/time as auxiliary geometry from the last accepted full PnP or local surface, not independent high-confidence filter measurements. Recheck their validity as the car moves.

Constant-velocity prediction: x += vx*dt, y += vy*dt, yaw = wrap(yaw+yaw_rate*dt). Use **continuous white-acceleration spectral density**, not fixed per-frame acceleration noise. For each pair (x,vx), (y,vy), (yaw,yaw_rate), insert `q*[[dt^3/3,dt^2/2],[dt^2/2,dt]]` into Q at state-index pairs (0,3), (1,4), (2,5). Start translational q=3.6 m^2/s^3 and angular q=(pi/3)^2*0.1 rad^2/s^3; increase densities in degraded/lost states. These retain the earlier 10 Hz velocity-noise scale while remaining consistent when time steps are subdivided. Initial standard deviations remain 0.5 m, 0.5 m, 2 degrees, 30 m/s, 30 m/s and 30 degrees/s. The undocumented GT quality field sets none of them. Local preflight verified one-second covariance equivalence at 10/20/30/60/120 Hz within 9e-15; production filter tests must repeat the property.

For an accepted current PnP pose, update `[x,y,yaw]` once, wrap its angular innovation and use a Joseph covariance update. Start pose-noise standard-deviation floors at 0.5 m/0.5 m/1 degree and inflate for weak support. For repeated shared-map observations use `R_eff=R_base*max(1,0.1s/dt_since_last_accepted_PnP)` to cap nominal information per second; a 60 Hz camera must not create six times the confidence from correlated map/calibration evidence. The first update uses 0.1 s. This is a conservative engineering rule, not calibrated probability. Velocity learns through filter correlations; do not add a finite-difference velocity measurement from the same PnP pose. No stale worker pose enters this update.

For a border-only correction, let the pre-update heading define `n=[-sin(yaw),cos(yaw)]`. Its measurement is lateral coordinate `n dot [x,y]` plus yaw; use a 2 x 6 observation Jacobian and noise floors 0.5 m/1 degree. This avoids a false along-track measurement. Shared calibration/feature errors still require conservative floors and empirical validation.

| Status | Initial transition rule | Behavior |
|---|---|---|
| Tracking | Verified full pose this group or within the last 0.5 s with usable tracking | Normal budget, absolute update preferred |
| Degraded | No accepted full pose for >0.5 s, but ground motion and/or border support remains | Grow uncertainty; activate rear evidence |
| Recovering | Lost absolute support, map enabled, recovery search active | Keep one uncommitted pose candidate; continue output |
| Lost | >1 s without usable visual evidence, >3 s without full position confirmation, or geometry startup failed | Predict with growing uncertainty, flag lost, preserve coverage, seek evidence |

For the supplied-border-only mode, report the actual evidence type and growing along-track uncertainty; border support alone never counts as a full absolute fix. A status label is an engineering state, not proof of accuracy.

Recovery uses **EigenPlaces ResNet18/512**, with fitting-reference descriptors precomputed and L2-normalized in a CPU matrix. Query RGB is 480 x 232 with ImageNet normalization, identical for references/queries. Vendor the author's MIT architecture/layers and load the full local checkpoint strictly; avoid the original constructor's redundant CosPlace download and all runtime hub access. Warm retrieval at 1 Hz, request it at the next eligible anchor slot when mapped support fails, and permit 2 Hz while recovering within the four-job/s ceiling.
